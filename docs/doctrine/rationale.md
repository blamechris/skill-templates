# Rationale for the fleet root

`assets/AGENTS.md` is the operative public doctrine. This document preserves the reasoning and evidence that was carried in the earlier `assets/global-CLAUDE.md` without making the root depend on historical narrative. The private, machine-local core goal and vault notes are outside this repository and are not source material here.

## Two authored nodes and five floors

The older arrangement compared a machine-authored `~/.claude/CLAUDE.md` with the registry copy on `origin/main`. Differences have different meaning: a floor divergence is a broken guarantee; a default divergence may be a legitimate local adaptation or a rule that has not yet been synchronized. The rule-class token belongs on the rule, not the heading, because headings change and the session-seed section mixes a floor with defaults. A stale clone cannot establish agreement, so comparison requires a fetch. A previous blanket “registry wins” resolution removed active machine conventions (#208); the machine-ahead delta must be considered before copying a registry version out. The new canonical path is `~/.fleet/AGENTS.md`, with family adapters loading it.

The seed floor exists because four loss paths recurred when continuity lived in the workspace: worktree teardown, branch reachability, staged versus committed state, and an unset session branch. The vault path is absolute and outside the worktree. `session-seed.py` is the single scope and write implementation. A hand-written git scope derivation was added to the most-read doctrine after the script was extracted (#210), illustrating why a second implementation drifts. The script refuses ambiguous git conditions instead of guessing `fleet`; the name `fleet` in a seed path does not change the distinction between fleet operations and portfolio products.

Three staging incidents in one week motivated explicit path staging. In one, `git add -u` included a tracked `.docx` that a git-lfs clean/smudge filter had rewritten, turning it into a pointer without an intentional edit. Worktrees make collisions structurally less likely, while branch assertions remain necessary in shared checkouts. Separately, Claude Code's harness-managed `agent-*` worktrees can disappear on cleanup even if a session intended to retain them. In the recorded case, the only path to stranded test blocks vanished 107 seconds before an issue's merge. Acceptance evidence therefore needs a durable branch, tag, or issue diff at filing time.

## Reporting and deliverables

The four-slot status block makes completed work, individual running agents, blockers and pending decisions visible at a glance. Its previous one-line form was retired because it did not scan in desktop/mobile views. A pending decision belongs in every block until resolved. The `Next` line assigns the next action after the block. A saved seed is only a file; it does not imply a scheduled continuation.

Long sessions use a concise HTML executive brief for verified outcomes and a lower section for detailed records. HTML deliverables for Chris default to a dark palette because the Claude app's local browser pane rendered pages light even when the OS used dark mode (#306). Product UI, third-party reports and claude.ai Artifacts have separate styling contracts. Delegated generators need the dark instruction in their own brief because they may never read the root.

## Skills and delivery

The registry is pull based: repos install and customize skills when needed. Push deployment was retired in #68/#75. `/project-genesis` handles a new repo before a local skill client exists; an established repo gets an audit and an explicit opt-in before changes. The delivery cadence couples implementation with observable acceptance, independent review, final-head checks and merge verification. A coordinator owns those gates after implementers finish. Delegated implementation carries ordinary gated merge authority, while review-only requests, unrelated PRs and explicit holds do not.

A merge does not show that a feature is in effect for users. The `In effect:` line records availability, observation outside tests and the remaining action without adding a merge gate. Normal development ends after the selected package and verified seed; prime-directive work checkpoints and continues within its authorized mission. Neither compaction nor a written handoff grants new authority or triggers a run. Usage checkpoints and benchmark rows are cumulative records whose per-run aggregation uses only the latest capture.

## Model choice, cost and review depth

The role policy names capabilities across providers: a workhorse can be Sol in Codex or Sonnet in Claude, while a coordinator uses the reasoning tier the package needs. This lets the fleet choose the available harness without forcing a vendor switch. The model ladder reserves the session ceiling for orchestration and hard adjudication and places mechanical work on the cheapest adequate model. The 2026-09-02 audit found four consecutive weeks with effectively no Haiku subagent spend despite a rule that said mechanical tasks should use it. Model choice must therefore be in the worker brief and review tool call, not only in doctrine.

Fable is restricted by blast radius and role, not a weekly dollar ceiling. The old $500 weekly ceiling was crossed mid-session without any agent consulting it. Meter evidence later showed that an earlier assertion of a $963 Fable week “without a clamp” was unsound; a measured reading pair put the Fable cap near $920. An all-models weekly cap measured across six periods had a central estimate near $2,363 but substantial spread, and the account reached the wall for roughly 29 hours in one period. Those are historical measurements, not constants for new sessions. The pacing script reads the current live percentage and age; stale post-reset samples cannot be treated as current. The usage accounting fix in #259 superseded partial transcript records with complete ones; pre-fix historical totals undercounted roughly 9% and cannot be directly compared with corrected totals. The unit represented by the plan meter was not conclusively established in the original rule, so readings retain dollars, raw tokens and input-equivalent tokens and the units comparison can report a tie. An honor-system limit that is never consulted does not limit anything; the hook surfaces pace while Fable is in use without blocking work.

Review depth follows blast radius. Refuters chiefly improved precision after a finder pass and test gates had already found issues, so LOW and MEDIUM use focused reviews and HIGH uses panels except for covered security/permissions work with a Codex pass. An earlier “~20 agents” wording was read as excluding refuters and led to workflows of 27–70 agents; the hard cap counts the whole workflow. Nitpicks do not need refuters. Reviews need a stable head so parallel reviewers, Copilot and Codex can feed one corrective push. Package reference figures ($15, $30, $45 by tier/depth) are benchmarks, never blockers. The original HIGH sample was sparse, so those figures remain provisional. The benchmark row's work suffix exists because spend alone could be measured precisely while delivered outcomes were buried in prose; `work: n/a` must not be converted to zero.

## Follow-ons and private findings

Blocking correctness, security, data integrity and promised acceptance findings require a fix or verified containment before merge. An issue link is a record, not a substitute for correcting the delivered behavior. Low-impact nonblocking issues can be tracked separately, and optional work should not displace the selected outcome. A verified fallback can preserve delivery when it meets safety, correctness, cost/runtime and essential capability requirements. Wait-only handoffs come after independent authorized work has advanced.

A currently exploitable weakness in a public default branch or release needs a private record and draft advisory so the report itself does not teach an unauthorized actor the exploit. The original public rule described the boundary, the vault record, subagent-to-coordinator handoff, advisory deduplication and neutral fix metadata. The initial compressed migration preserved the broad policy but omitted operative details, including the list and create commands. The correction restores the policy clauses in the root and moves the advisory commands into `assets/scripts/private-advisory.sh`, with reviewed-list deduplication and fake-`gh` tests. The earlier migration must not be described as preserving every operative requirement. An unmerged-only weakness and an already published dependency advisory remain ordinary public review and upgrade work. A fix can disclose the weakness through branch, test, log or PR wording even if the initial finding stayed private, so metadata must describe the resulting behavior accurately without exploitation detail.

## Waiting on external work

The desktop PR monitor wakes on failures, conflicts and comments, but not green CI. A single bounded watcher supplies a green wake and triggers fresh final-head gate verification. A long process with no ceiling may never produce the completion event the harness waits for. The root therefore requires a timeout, success marker and progress check-in, with the CI watcher itself serving that role for CI. These rules turn stalled work into an observable failure or runner incident rather than an indefinite silent wait. The long-job behavior shipped in the canonical root; #406 was closed as superseded. Its timeout, incident and liveness requirements remain operative.

## Correction audit

The initial compressed root kept the floor blocks and rule IDs but dropped small operational clauses from several defaults. The correction rewrites defaults as complete sentences and restores the missing instructions. [The clause audit](root-clause-audit.md) records the behavior checked rule by rule, without copying private machine direction or historical session records into this repository. The root owns agent behavior; scripts own the scope derivation and advisory command implementation. History and measurements in this rationale do not replace operative rules.
